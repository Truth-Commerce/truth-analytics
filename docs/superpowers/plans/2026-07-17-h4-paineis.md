# H4 — Painéis do Analista e do Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Painel do analista no mínimo 3x mais completo (command center da carteira com score de risco, visão 360 por cliente, inteligência comparativa, pauta IA por ciclo) e painel do admin com controle total (visão global, centro de operações com custo IA consolidado e heartbeat de crons, gestão completa de contas, impersonation read-only auditado).

**Architecture:** Camadas de leitura dedicadas (`src/modules/analista/` expandida + `src/modules/admin/`), toda query com escopo explícito (carteira via `assertOrgAccess`/`analista_id`; admin via `requireAdmin`). Score de risco = função pura com insumos batizados. Pauta IA = passo 4 dos extras pós-finalize (espelho do padrão graceful de kits/calendário), persistida em `analyst_briefings` com usage em `reports.briefing_ia_usage`. Heartbeat de crons = tabela global `cron_heartbeats` gravada best-effort ao fim de cada rota de cron. Impersonation = cookie HMAC (AUTH_SECRET, 30min) resolvido CENTRALMENTE em `requireActiveOrg` (admin vira UserAccess sintético read-only); mutações do cliente migram para `requireActiveOrgParaMutacao` (rejeita impersonação); início/fim auditados + banner fixo. **Painel do CLIENTE não muda** (invariante do spec).

**Tech Stack:** os mesmos (Next.js 14 RSC, Drizzle+Neon, charts Recharts existentes — 11 componentes prontos, @anthropic-ai/sdk padrão). Sem lib nova; sem env nova.

**Branch:** `feat/h4-paineis` (base: `master`).

**Decisões de plano:**
- Score de risco (spec: função pura, pesos definidos aqui): insumos e pontos — token Bling `expirado`=30 / `erro`=25 / expirando<72h=15; relatório: último `failed`=25, nenhum done há mais de (dias do plano + 7)=20; queda de vendas (total 7d < 50% média 4 semanas — reusa a matemática dos alertas)=20; SLA: cada task atrasada=5 (cap 15); estoque: cada sku crítico=4 (cap 12); meta em risco (pace < 80% no dia 15+)=10. Score = soma (cap 100); faixas: ≥50 crítico / ≥25 atenção / senão ok. Motivos = lista pt-BR dos insumos disparados.
- Pauta IA gerada para org COM analista atribuído (`analista_id IS NOT NULL`) — sem analista, sem pauta (economiza IA).
- `cron_heartbeats`: pk = rota (varchar 64), `executado_em`, `ok` bool, `detalhes` jsonb — UPSERT best-effort no FIM de cada rota de cron (nunca quebra o cron). Global (sem org): NÃO entra no purge.
- `analyst_briefings`: org-FK → ENTRA no purge na mesma task do schema (lição institucionalizada).
- Impersonation: "não é truque de cookie" do spec = a RESOLUÇÃO é central e tipada no funil de acesso (não checks espalhados por página); o transporte é cookie httpOnly assinado (mesma classe do state-cookie CSRF do OAuth já existente no projeto). Read-only por construção: TODAS as mutações do cliente usam o require novo que rejeita sessão impersonada.
- Meu-dia (G3) é PRESERVADO: integra como seção do command center novo (não deletar).
- Follow-up H3 fechado aqui: custo IA consolidado = ia_usage + kits_ia_usage + calendar_ia_usage + briefing_ia_usage no centro de operações.
